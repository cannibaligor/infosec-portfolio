01

Analisador de URL

Mostra para onde um link leva de verdade, sem abrir o link, e aponta os truques usados em phishing.

Quando usar

  • Um usuário reportou um e-mail suspeito e você precisa saber o destino do botão.
  • Um alerta de proxy ou DNS trouxe uma URL estranha.
  • Antes de mandar a URL para o VirusTotal ou para o ticket.

Como usar

  1. No e-mail, clique com o botão direito no link e escolha Copiar endereço do link. Nunca clique nele.
  2. Cole aqui (pode estar com defang, tipo hxxps e [.]).
  3. Clique em Analisar.

Como ler o resultado

  • Host real (verde): é para lá que o navegador vai. O que está riscado é ignorado.
  • Domínio registrado: quem é o dono. Compare com a marca que o e-mail diz ser.
  • Pontos de atenção: vermelho pesa mais. Nenhum sinal não prova que é seguro.
  • Copie a linha Para o ticket (já com defang).
Exemplo prático

O e-mail do "DETRAN" tinha um botão "Consultar infração". O link parecia ser do office.com. Veja onde ele realmente leva e compare com um link legítimo do gov.br.

02

Analisador de cabeçalhos de e-mail

Lê os cabeçalhos técnicos que o Outlook esconde e mostra de onde o e-mail saiu, por onde passou e se passou na autenticação.

Quando usar

  • Todo e-mail reportado como phishing.
  • Quando você precisa do IP real de envio para denunciar ou bloquear.
  • Para confirmar se o remetente é quem diz ser.

Como usar

  1. No Outlook web: abra a mensagem, ⋯ → Exibir → Exibir origem da mensagem (em versões antigas, "Exibir detalhes da mensagem"). No Gmail: ⋮ → Mostrar original.
  2. Copie tudo até a primeira linha em branco (o corpo não é necessário).
  3. Cole aqui e clique em Analisar.

Como ler o resultado

  • Caminho: o nº 1 (vermelho) é a origem real. Os Received são lidos de baixo para cima.
  • SPF/DKIM/DMARC: verde é pass. none = nada a verificar, fail = falhou.
  • pass só prova que aquele domínio enviou. Golpista também consegue pass no domínio dele.
  • SCL 5 ou mais: a Microsoft já achou que era spam.
Exemplo prático

Versão simplificada dos cabeçalhos do caso DETRAN (horários e IDs ilustrativos). Note o 1º salto se apresentando como localhost e a autenticação toda em none.

03

Extrator de IOCs

Tira de qualquer texto os indicadores que importam: IPs, URLs, domínios, e-mails, hashes, CVEs e técnicas MITRE, sem repetição.

Quando usar

  • Para montar a lista de bloqueio de um incidente.
  • Para ler rápido um relatório de ameaça ou um JSON de alerta grande.
  • Para preencher o campo de IOCs do ticket.

Como usar

  1. Cole o texto: e-mail, alerta do Wazuh em JSON, log, relatório.
  2. Deixe saída com defang marcado se for para ticket ou chat.
  3. Clique em Extrair e depois em Copiar lista.

Como ler o resultado

  • IPs marcados como privado/interno são da sua rede: não vão para lista de bloqueio externa.
  • Revise os domínios: nomes de servidores legítimos (outlook.com, por exemplo) também aparecem.
  • IOC bom é o que identifica o atacante, não a infraestrutura de todo mundo.
Exemplo prático

Um trecho de alerta do Wazuh (brute force do Cenário 1) junto com as anotações do caso de phishing. Veja o que sai e o que você deveria descartar.

04

Defang e refang

"Desarma" URLs, IPs, domínios e e-mails para que não virem links clicáveis em tickets, chats e relatórios. O refang desfaz.

Quando usar

  • Sempre que um indicador malicioso for para um lugar onde alguém pode clicar: Teams, Slack, e-mail, ticket.
  • Refang: quando você recebe um IOC desarmado e precisa colar numa ferramenta (bloqueio no firewall, busca no SIEM).

Como usar

  1. Cole um ou vários indicadores, um por linha ou no meio de um texto.
  2. Clique em Defang (ou Refang).
  3. Clique em Copiar.

Como ler o resultado

  • https vira hxxps, cada ponto vira [.] e o @ de e-mails vira [@].
  • O texto continua legível para humanos, mas nenhum programa transforma em link.
Exemplo prático

Você vai avisar o time no chat sobre o IP e a URL do golpe. Desarme antes de mandar.


          

        

      


      

        

          
05
Decodificador de PowerShell

          
Revela o comando escondido num -EncodedCommand (Base64 de UTF-16LE) e aponta o que é perigoso nele.

          
Quando usar

          
  • Um alerta como o 92057 mostrou powershell -enc … na commandLine.
  • Um serviço (7045) ou tarefa agendada chama PowerShell com Base64.
  • Você não tem o evento 4104 para ver o código já decodificado.

          
Como usar

          
  1. No alerta, copie o campo commandLine inteiro (ou só o Base64).
  2. Cole e clique em Decodificar.
  3. Codificar texto faz o caminho inverso, útil para testes no lab.

          
Como ler o resultado

          
  • O quadro mostra o código que rodou (o mesmo que o 4104 registraria).
  • Alto: download, IEX, injeção de memória, Defender, persistência. Escale.
  • Info sozinho (Write-Host, Get-Date) tende a ser teste ou administração. Confirme com quem rodou.

        

        

          
Exemplo prático
Compare o teste benigno do Cenário 2 com um "download cradle" malicioso. O formato é o mesmo; o conteúdo decide a gravidade.

            

          
          
          

          

        

      


      

        

          
06
Hash de evidência

          
Calcula a "impressão digital" (SHA-256 e SHA-1) de um arquivo ou texto e confere se bate com um hash esperado.

          
Quando usar

          
  • Ao salvar uma evidência (.eml, log exportado): registre o hash no ticket. É a cadeia de custódia.
  • Para pesquisar um anexo no VirusTotal pelo hash, sem enviar o arquivo.
  • Para provar que um arquivo não mudou desde a coleta.

          
Como usar

          
  1. Clique em Escolher arquivo (ele é lido só aqui) ou digite um texto e clique em Hash do texto.
  2. Para conferir, cole o hash esperado no campo Comparar com.

          
Como ler o resultado

          
  • Mudou um único byte, o hash muda inteiro.
  • Confere: é o mesmo conteúdo. Não confere: foi alterado ou é outro arquivo.
  • Hash não é criptografia: não esconde nada.

        

        

          
Exemplo prático
Duas versões de um texto que diferem só numa letra. Veja como os hashes ficam completamente diferentes e o comparador acusa a mudança.

            

          
          
          
          
          

          

        

      


      

        

          
07
Conversor de horário

          
Converte um horário entre UTC, o fuso do dashboard do lab (UTC−4), Brasília e o seu computador.

          
Quando usar

          
  • Para montar uma linha do tempo com eventos de fontes diferentes.
  • O dashboard mostra um horário, o evento do Windows (systemTime) mostra outro: os dois estão certos, em fusos diferentes.
  • Para escrever o relatório num fuso só.

          
Como usar

          
  1. Cole o horário como aparece (dashboard, JSON, epoch).
  2. Escolha em que fuso ele está.
  3. Clique em Converter.

          
Como ler o resultado

          
  • Use a linha UTC para comparar com o systemTime dos eventos do Windows.
  • Epoch é o mesmo instante em segundos: útil para buscas e scripts.

        

        

          
Exemplo prático
No dashboard do Wazuh, o alerta 60204 aparece em Nov 14, 2026 @ 01:57:04.000. O evento 4625 do Windows diz 05:57:04. É o mesmo momento?

            

          

            

            

          

          

          

        

      


      

        

          
08
Calculadora de correlação

          
Simula uma regra de frequência do Wazuh, como a 60204: quantos eventos, em quanto tempo, fazem o alerta grave disparar.

          
Quando usar

          
  • Para entender por que um ataque gerou (ou não) o alerta correlacionado.
  • Para explicar numa entrevista como funciona correlação.
  • Para perceber o ponto cego: ataques lentos passam por baixo da janela.

          
Como usar

          
  1. Preencha quantas falhas houve e o intervalo entre elas.
  2. Preencha o frequency e o timeframe da regra (estão no XML dela).
  3. O resultado atualiza sozinho.

          
Como ler o resultado

          
  • Dispara: diz em qual falha e quantos segundos depois da primeira.
  • Não dispara: diz o motivo (poucas falhas ou lentas demais).

        

        

          
Exemplo prático
O Cenário 1 teve 9 falhas a cada ~2 s. Compare com um atacante paciente que tenta uma senha por minuto.

            

          

            

            

            

            

          

          

        

      


      

        

          
09
Referência rápida

          
Event IDs do Windows e do Sysmon, tipos de logon, códigos do 4625, regras vistas no lab e técnicas MITRE do portfólio.

          
Quando usar

          
  • Apareceu um número que você não lembra (4648? logonType 9? 0xC0000234?).
  • Para escolher o Event ID certo numa busca no SIEM.

          
Como usar

          
  1. Digite um código ou palavra (RDP, lsass, bloqueada).
  2. Ou filtre pela categoria nos botões.

        

        

          
Exemplo prático
Num 4625 aparece subStatus 0xC000006A. O que significa?
